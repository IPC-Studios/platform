# Live parity: the old app vs this one

Generated by walking both **deployed** apps and fingerprinting every screen —
the tabs, wizard steps, field labels, table columns and buttons a user can
actually see. Not a code comparison.

- Old: `https://ipcstudio.lovable.app`
- Ours: `https://ipc-web.dev-d9b.workers.dev`

## Why this file exists

Earlier parity passes checked whether a route or endpoint *existed*. That finds
things that are missing outright — a whole module with no UI, a function that
throws. It cannot find a screen that exists but offers a fraction of the
original, which turned out to be the common case: the project editor was 226
lines against 853, and the Terms tab is one button where the old app has a
three-step document wizard with a live preview.

Existence is not equivalence. This compares what is on the screen.

## How to read it

`missing` counts old-app items with no match anywhere on our matching screen,
after normalising case, whitespace, currency symbols and digits. **It is a
lead, not a verdict.** Two known sources of false positives:

1. **Naming.** "Add client" vs "New client" is not a gap.
2. **Rendering.** Where the old app keeps all wizard steps in the DOM at once
   and we mount one step at a time, its snapshot shows fields ours has simply
   not rendered yet.

Every row needs eyes on it before it becomes work. The rows already verified
are marked.

## Verified findings

### Production board — real
Ours has Status / People / Data views and project, priority and assignee
filters. The old app adds:
- **Any due** and **Any data** filters, and an **Assigned + Unassigned** toggle
- Lane KPI chips with counts: Overdue, Due Today, Pending Review, In Progress,
  Completed, Needs Attention
- A **Details** panel

### Clients — partly real
Ours has search, a relation filter, sort presets, CSV export and a New client
button. Genuinely missing:
- **Created from / Created to** date filters
- **Address** and **Added** (date) columns
- Row-level **Edit** and **Delete**

The other items the diff flagged are naming differences.

### Project → Terms tab — real, and the largest single gap
The old app is a three-step document wizard:
1. **Template & Payment Terms** — template picker, Apply template, Seed,
   Document title, and six payment presets (`30/30/30/10`, `30/40/30`,
   `50/50`, `100% Advance`, `Retainer + Balance`, `Custom`) plus Advanced edit
2. **Terms & Conditions**
3. **Send to Client**

With a **live preview** that re-renders as you type, **Save draft**, **Generate
PDF**, a draft badge, and a warning when company branding is incomplete that
links to Settings.

Ours: a single **Issue terms** button and a list of sent documents with Resend.

### Facebook lead inbox — real
Covered already: the Meta connection and per-source import log now exist, but
the old app's dedicated FB leads inbox (filters, summary cards, per-lead
confirm dialog) does not.

## Re-running this

1. Open both apps logged in, in one tab each.
2. Inject the fingerprint function and walk the route list.
3. `navigator.clipboard.writeText(JSON.stringify(capture))` moves the result
   out of the browser in one step — reading it back through the tool is
   truncated, the clipboard is not.
4. Diff with `scratchpad/diff.py`.

Wait at least 1.5s per route; data-heavy screens captured empty at shorter
waits, which is what produced the six `CAPTURE FAILED` rows.
